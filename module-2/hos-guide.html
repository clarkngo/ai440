HOS 2: Physics-Informed Neural Networks

Train a physics-informed neural network in plain PyTorch on CPU that predicts the temperature inside a building wall through a cold snap, compare it with a data-only network where the twin actually needs predictions, then make the wall's diffusivity something the PINN learns.

Est. 4–5 hrsCO2Module 2 · Weeks 3–410% of final grade

🧭

Before you start

  1. Know the concepts. Read Concept Companion → Module 2 and try its self-check before you open the starter code.
  2. Rehearse it. The Wall Heat PINN Simulator plays the finished build in your browser; its guided tour takes about 15 minutes.

What you'll need

  • Starter code: your own HOS 2 repo, opened in GitHub Codespaces. Planned The HOS 2 starter repository and its GitHub Classroom invite are being built and tested; the invite link goes here when they are published. Not sure what a file does? See the starter code walkthrough for this HOS.
  • A GitHub account. No GPU and no paid service: PyTorch (the CPU build) and DeepXDE are free.
  • The default 2-core Codespace. Training the PINN takes 2–5 minutes; the data-only network under a minute.

Reference reading (optional, before you start)

  • PyTorch: automatic differentiation with torch.autograd: how torch.autograd.grad gives derivatives of the network's output.
  • DeepXDE forward-problem demos: the same kind of problem in a PINN library, for the Analyze mapping.
  • Raissi, Perdikaris & Karniadakis (2019): the paper that introduced physics-informed neural networks.

This HOS is graded across four stages instead of on code correctness alone: Engagement (Create/Scaffold) is 20% of the HOS grade, and Skills is 80%: Evaluate, Analyze, Apply (the change you make by hand in Understand & Refine) and Understand (your own explanation of it), 20% each. Each stage below says exactly what to submit. Everything goes in your Module 2 GitHub Classroom repo: written work under the matching heading in NOTES.md, screenshots in screenshots/. Commit and push as you go. By the end of Week 4, push your final work: your repo is your submission, so there is nothing to submit in Brightspace, and your last push before the deadline is what counts.

1 · Create / Scaffold

Week 3 · Wed–Thu

Graded as Engagement: 20% of this HOS. The AI-built starting point, not the deliverable.

Get a working PINN with an AI coding assistant: the network, the three loss terms and the training loop, in plain PyTorch on CPU. The readings, a data-only network and a comparison script are already in the starter. This is the starting point, not the deliverable; whether it is right is what Evaluate is for.

  1. Open your own HOS 2 repo in GitHub Codespaces (its .devcontainer installs CPU-only PyTorch and DeepXDE). Planned The HOS 2 starter repository and its GitHub Classroom invite are being built and tested; the invite link goes here when they are published.
  2. Train the data-only baseline first and look at its plot: python compare.py --model data. It writes plots/data_only.png.
  3. Give your assistant the prompt below, then run python compare.py --model pinn and python compare.py --model both.

The prompt

Use an AI coding assistant in Agent mode (GitHub Copilot is free for students in Codespaces). Give it this prompt as written, and read what it changed before you run anything:

In THIS existing workspace (the starter-code folder that's already open),
edit files here; do not create a new workspace or project.
In models/pinn_torch.py, write a physics-informed neural network in
plain PyTorch (CPU only; no GPU, no DeepXDE) for heat flow through
the wall: du/dt = ALPHA * d2u/dx2.
- Import ALPHA, L, T_IN, T_OUT and T_END from physics.py, and load
  the readings with load_readings() from data.py.
- The network takes (x, t), both scaled to [0, 1], and returns the
  temperature: 3 hidden layers of 32 tanh units. Rescale ALPHA to
  match the scaled inputs, and say how in a comment.
- loss = data term (MSE at the readings)
       + LAMBDA * physics term (mean squared heat-equation residual
         at random collocation points over the whole wall and all
         of T_END, derivatives from torch.autograd.grad with
         create_graph=True)
       + boundary term (u = T_IN at x = 0, u = T_OUT at x = L)
- train(lam=1.0, n_col=2000, epochs=5000, seed=0) returns the model
  and a history of each loss term every 100 epochs.
- It must finish in under 5 minutes on a 2-core Codespace.
- Make python compare.py --model pinn work and pytest pass.

Gotchas to expect: (1) The assistant may build in a new workspace instead of your starter folder; use Agent mode and say "this existing workspace". (2) If it installs a CUDA build of PyTorch, the Codespace runs out of disk and the install fails; the starter pins the CPU wheel, so don't let it change requirements.txt. (3) A PINN that "trains" but whose physics loss never drops usually lost requires_grad on the collocation points, or forgot create_graph=True.

Submit (Engagement)

  • Paste the prompt you gave your AI assistant under Create in NOTES.md, add plots/both.png and a screenshot of compare.py's error table to screenshots/, then commit and push to your Module 2 repo.

2 · Evaluate

Week 3 · Fri–Sun

The critical gate — is the AI-built result actually right?

Is the AI-built PINN actually right, and is it better than the data-only network where it matters? compare.py scores both models against a reference solution in three regions: at the sensors, between them, and past the data. Run each of these and write down what happened:

  • Between and beyond: read the error table from compare.py --model both. Where does the data-only network lose, and by how much? Is the PINN better everywhere?
  • Physically impossible: run compare.py --check-physics. Does either model predict anywhere below −5 °C or above 21 °C, which the maximum principle rules out?
  • Wrong physics: retrain with --alpha-scale 0.5 and --alpha-scale 1.5 (a wrong spec sheet). What does the PINN predict at hour 12, and does anything in the loss history warn you?
  • Cost: how long did each model take to train on two cores? Then run the library version, python -m models.pinn_deepxde. Same answer? Same time?

Submit

  • Paste this note under Evaluate in NOTES.md, add the plots and tables to screenshots/, then commit and push by the end of Week 3. Your commit history is your Week 3 checkpoint.

3 · Analyze

Week 4 · Mon–Tue

Why does this work, mechanically?

Pick one of these and explain it in your own words. Depth beats breadth: one mechanism explained well scores higher than a tour of every file. Your instructor may ask a follow-up about one line, so write it so you could answer.

The loss, term by term

What each term teaches the network, and how autograd gives the derivatives.

  • Explain each term of your loss in one sentence, and what the model does if you delete it.
  • Quote the lines where torch.autograd.grad gives du/dt and d²u/dx². Why is create_graph=True needed for the second one?
  • What does your loss history show about which term the optimizer fought hardest, and when?

The collocation points

Why the physics is checked where there are no readings.

  • Why is the physics term computed at random points where there are no readings? What is the residual compared with there?
  • Retrain with n_col=50 instead of 2,000. Where do the errors appear, and why there?
  • Why sample all twelve hours, not just the three with data?

Your PINN vs. DeepXDE

Map each piece of the library version to a line of yours.

  • Map each object in models/pinn_deepxde.py (geometry and time domain, PDE, boundary conditions, observed points, network) to the lines of your PyTorch PINN.
  • What does DeepXDE do for you that your version doesn't, such as point sampling or loss weights?
  • What would be harder to debug if you had started with DeepXDE?

Submit

  • A short written walkthrough of the one you chose, under Analyze in NOTES.md, quoting the lines you explain, with a screenshot of the run you describe in screenshots/.

4 · Understand & Refine

Week 4 · Wed–ThuNo AI assistant for this part

The mastery check — by hand, no AI assistance for this stage.

By hand this time. Turn off your AI assistant (Copilot: the status-bar icon, then Disable completions) and close its chat. Docs, the lecture and your own Week 3 code are fine.

The spec sheet's diffusivity is a guess, and Evaluate showed what a wrong guess does. Make α a parameter the PINN learns from the readings: by hand, in models/pinn_torch.py.

  1. Write two sentences: why a learnable α should help when the spec sheet is wrong, and one thing it can't fix.
  2. By hand, replace the fixed ALPHA with log_alpha = torch.nn.Parameter(...) (so α stays positive), start it at the spec-sheet value, and add it to the optimizer.
  3. Retrain with --alpha-scale 1.5 --learn-alpha, and record the learned α every 500 epochs.
  4. Compare its errors with the fixed, wrong-α PINN in all three regions. Screenshot the compare.py table.
  5. Explain in 3–4 sentences what the readings taught the model, and one situation where learning α would not have helped (a wrong equation, not a wrong number).

Submit

  • Apply: The learnable α you wrote by hand in models/pinn_torch.py is committed, and compare.py --learn-alpha works.
  • Understand: your own explanation under Understand & Refine in NOTES.md, with its screenshots in screenshots/.
  • Then push by the end of Week 4. Your repo is the submission; the last push before the deadline counts.

Common snags

  • The physics loss stays flat — the collocation points lost requires_grad=True, or the second derivative was taken without create_graph=True on the first. Print the residual's grad_fn; None means the graph is broken.
  • The loss is nan after a few hundred epochs — unscaled inputs or too high a learning rate. Scale x and t to [0, 1] (and α with them) and try lr=1e-3.
  • pip fills the disk — a CUDA build of PyTorch (several GB). Keep the starter's pinned CPU wheel in requirements.txt and reinstall from it.
  • Training takes 20 minutes — too many collocation points or epochs for two cores. The starter's defaults (2,000 points, 5,000 epochs) are sized for under 5 minutes.
  • DeepXDE complains about its backend — set DDE_BACKEND=pytorch; the .devcontainer does this, so a new terminal outside it may not.
  • The assistant created a new folder or project — it built in a new workspace instead of your starter. Delete what it made, reopen the repo folder, and say "this existing workspace" in Agent mode.

Most snags trace back to a concept. If one doesn't make sense, see Concept Companion → Module 2.
